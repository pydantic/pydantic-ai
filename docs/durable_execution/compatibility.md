# Durable Engine Compatibility

A durable engine has to run a capability's tools so that recovering a run repeats none of their work, and replay
what the run observed, such as the events a tool emits. Pydantic AI checks this per engine with a conformance suite,
[`DurableEngineSuite`][pydantic_ai.durable_exec.conformance.DurableEngineSuite]: it runs each capability's tool calls,
and each scenario below, under the engine, recovers the run, and checks what the engine recorded and what the
recovered run did. The tables below are generated from what each engine declares, and the suite checks every cell
on each change.

- **Supported**: recovering a run repeats no completed model request or tool call, records the same units, and
  observes the same events and messages.
- **Limited**: the same, with a limit the cell names.
- **Refused**: the engine raises a [`UserError`][pydantic_ai.exceptions.UserError] before the refused operation
  records anything, leaving what the run recorded before it intact.
- **Broken**: the engine runs it and gets it wrong; the linked issue tracks the fix.

Recovery is what an engine does after a crash: an engine that **replays** the record returns each completed call's
recorded result. One that **restarts** makes every call again, so all its cells are limited.

The scenarios check more than one call per response:

- `BackgroundTools.runs_in_background`: a tool marked `background` replies that it is running in the background,
  and its result arrives later as a follow-up message.
- `BackgroundTools.survives_approval_wait`: while that call is still running, the model calls a tool that needs
  approval, which is answered mid-run. The call keeps running across the wait, and its result arrives.
- `RunContext.emit_*` and `RunContext.enqueue_*`: [`ctx.emit`][pydantic_ai.tools.RunContext.emit] and
  [`ctx.enqueue`][pydantic_ai.tools.RunContext.enqueue] from a function tool, from inside a durable unit (a
  [`@durable_operation`][pydantic_ai.capabilities.durable_operation]), and from a hook. The recovered run must
  observe each event and message once.
