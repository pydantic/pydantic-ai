# CLAI 2 file map

What each module under `pydantic_clai2/` holds, for finding where a change belongs.
`AGENTS.md` points here rather than inlining it, because `AGENTS.md` is sent with every request.
Keep a row current when you add, move, or change the responsibility of a module.
One CLAI process holds one `ClaiProcess` and one `SessionRuntime` per live session; put
what exists once on the first and what each session has on the second (see "Per session on
`SessionRuntime`, per process on `ClaiProcess`" in `AGENTS.md`).

| File | Holds |
|---|---|
| `cli/cli.py` | argument parsing, startup, `--agent`, `--update` |
| `cli/agent_import.py` | resolves `--agent MODULE:ATTR` to an agent instance |
| `cli/self_update.py` | `/update now`, `clai2 --update`, the update menu's check (`Updates.check`), and the status-row notice: PyPI (`stable`) or the `clai2-bleeding` GitHub release (`main`: sdists built from the `main` branch by `.github/workflows/clai2-bleeding.yml` with `scripts/build_bleeding.sh`, installed with `--overrides`, no git or GitHub API; `CLAI_BLEEDING_URL` points it elsewhere), reinstalled with `uv tool install --force --compile-bytecode`; `InstallProgress` tells plugins how the install goes, and `Relaunch` carries a `WebHandoff` so the new build serves the web UI again |
| `app.py` | `chat`, the terminal app around the session it starts (startup resume, `/reload`, `/update` restarts) and the ones the web UI opens beside it (`_opener`), and `open_stock_agent`, the stock agent for code outside the terminal |
| `runtime/process.py` | `ClaiProcess`: what every session in one CLAI process shares: the settings and conversation stores, the one delegated-task owner (`TaskRouter`), the one `SessionNamer`, the Codex provider per account (`codex_providers`) every session's `ModelResolver` shares while signing in on its own console, `ProcessPlugins`, and `live`, the `LiveRuntimes` |
| `runtime/live_runtimes.py` | `LiveRuntimes`, the process's live sessions as `host.live` reaches them: listing by ID, the session holding a conversation, `open` (one session per conversation, concurrent opens included; a busy one opens its existing fork), `new`, `close`, `subscribe`; `serving` runs the sessions it opens with `build` as tasks and closes idle ones (`IDLE_AFTER`, `close_idle`); `/set` fan-out to the other sessions, except `model` and `run.*` |
| `runtime/session_runtime.py` | `SessionRuntime`, one live session: its prompt loop, built-in `/commands`, plugin loader, input queue (the editor's while the terminal shows it, else a `PromptInbox`; `queue`, `edit_queued`, `remove_queued`, and `steer` for `host.live`), and turns; `running`, `queued`, and `idle` state; `serve`, a session with no terminal from start to close; `create_shell` builds one over a `ClaiProcess` and adds it to its `live` sessions, shown in a new `Terminal` unless headless; `shown_in` and `show_live` move the terminal between sessions; `/reload` and `/update now` are refused while other sessions run turns, in a shown session from another folder, in the first session while hidden, and in a served one while not shown; bare `/update` can still show its menu in the shown terminal session; the `/update` menu `Command.menu` builds (`host.command_menu('update')`, the web UI's About) raises a refused Update as `ValueError` |
| `models/resolver.py` | `ModelResolver`: model names to models, loading provider integrations on demand, with accounts, profiles, and `chain:` fallbacks |
| `runtime/session.py` | conversation state, revision-checked saves (each recording the Git checkout of the session's directory), restore-only resume (a session busy in another process resumes in its existing fork, else a new saved fork: `continuing_fork`, `busy_elsewhere`), plugin snapshots and stock-agent rebuilding |
| `runtime/project_identity.py` | the repository and checkout of a session's directory, for `/resume` and the web sidebar: `project_identity` reads Git, `worktree_roots` lists a repository's worktrees for New session, `placements` places removed folders by the saved checkout, a known checkout, or a worktree layout, else under `MISSING` |
| `runtime/sessions.py` | resume command, and the session's `NamingClient` and title listener on the process's namer; the `SessionCatalog` plugins reach as `host.sessions` (list, read, rename, fork, archive, delete saved sessions; archiving is the harness store's `archived_at`, and resuming unarchives); built-in step capture |
| `runtime/imported_sessions.py` | Claude Code and Codex sessions for `/resume`, `--resume-claude`, and `--resume-codex`: the on-disk catalog, stable CLAI IDs, and copying into the store (re-reading an uncontinued copy on every resume), with Claude Code's sub-agents saved as the copy's tasks |
| `runtime/claude_code_sessions.py`, `runtime/codex_sessions.py` | read each agent's JSON Lines transcripts: headers for the browser (Claude Code's session names), and the history to continue between notes on the change of harness: the last Claude Code branch with its parallel tool results, and Codex's whole history with its compactions as `openai-codex` boundaries; each agent's harness context, and its sub-agents as tasks |
| `runtime/imported_history.py` | shared transcript reading (`records`, `tail_records`) and `HistoryBuilder`, which groups parts into requests and responses; core's `repair_messages` pairs the tool calls; `imported_context` tags what another agent's harness added, `framed` adds the notes on the change of harness, `final_answer` reads a sub-agent's, and `is_typed_prompt` tells the user's own prompts apart |
| `runtime/session_naming.py` | resume-browser naming prompt, `SessionName` card schema, and the bounded `SessionNamer` worker, shared by the process's sessions; each queues with its own `NamingClient` (model, setting), and every session hears titles through `listeners`, retitling the conversation it holds |
